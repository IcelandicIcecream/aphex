title: Reference
description: Links to other documents with a searchable picker.
---

The `reference` type creates a relationship between documents. It renders a searchable dropdown that lets users pick from existing documents of the specified type.

## Definition

```ts
import type { ReferenceField } from '@aphexcms/cms-core';
```

```ts
{
  name: 'author',
  type: 'reference',
  title: 'Author',
  to: [{ type: 'person' }],
  validation: (Rule) => Rule.required()
}
```

## Properties

| Property       | Type                               | Required | Description                                                                                                       |
| -------------- | ---------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `name`         | `string`                           | Yes      | Field identifier.                                                                                                 |
| `type`         | `'reference'`                      | Yes      | Must be `'reference'`.                                                                                            |
| `title`        | `string`                           | Yes      | Label shown in the admin UI.                                                                                      |
| `description`  | `string`                           | No       | Help text shown below the label.                                                                                  |
| `to`           | `Array<{ type: string }>`          | Yes      | Document types this field can reference. Currently only the **first** type in the array is used by the component. |
| `initialValue` | `any \| () => any \| Promise<any>` | No       | Default value.                                                                                                    |
| `weak`         | `boolean`                          | No       | May point at a draft: see [Weak references](#weak-references).                                                    |
| `validation`   | `(Rule) => Rule`                   | No       | Validation rules.                                                                                                 |

## Examples

### Single type reference

```ts
{
  name: 'category',
  type: 'reference',
  title: 'Category',
  to: [{ type: 'category' }],
  validation: (Rule) => Rule.required()
}
```

### Author reference in a blog post

```ts
const post = defineType({
	type: 'document',
	name: 'post',
	title: 'Blog Post',
	fields: [
		{ name: 'title', type: 'string', title: 'Title' },
		{
			name: 'author',
			type: 'reference',
			title: 'Author',
			to: [{ type: 'author' }],
			validation: (Rule) => Rule.required()
		},
		{ name: 'body', type: 'text', title: 'Body' }
	]
});
```

## Weak references

A document can't be published while a reference in it points at a document that isn't published, so the live site never points at nothing. For links that's too strict: two pages that link to each other could never go live, each waiting for the other. Mark such a field `weak: true`, as in Sanity, and it may point at a draft; the site shows the link once its target is live.

```typescript
{
  name: 'page',
  type: 'reference',
  title: 'Page',
  to: [{ type: 'page' }],
  weak: true
}
```

In an array, put `weak: true` on the reference item: `of: [{ type: 'reference', to: [{ type: 'page' }], weak: true }]`. It's read from the schema when publishing, so references saved before a field was made weak count as weak too.

## UI Features

**When no reference is selected:**

- Searchable dropdown showing documents of the target type (first 10 results)
- Each row honors the target schema's `preview.select.title` and `preview.select.subtitle` (with dot-path support) — if you configure a subtitle, the picker shows two lines
- "Create new" button to create a referenced document on the fly

**When a reference is selected:**

- Shows the referenced document's title (and subtitle, when the target schema declares one), type icon, and status dot (draft / published / unpublished)
- Button to open the referenced document in the editor
- Button to clear the selection

<Callout type="info">
	**Reference traversal in preview is not supported yet.** A reference field stores only an ID —
	`preview.select.title: 'pageReference.title'` won't resolve the linked document's title. Either
	denormalize a snapshot field on the parent document or wait for `depth: 1` threading on the picker
	fetch (planned).
</Callout>

## Stored Data

Both singular and array references use the same on-disk shape:

```ts
{
	author: { _type: 'reference', _ref: 'document-id-123' }
}
```

This is the same `{ _type, _ref }` shape used by array-of-reference items, which also include a `_key` for stable ordering:

```ts
{
	items: [
		{ _type: 'reference', _ref: 'item-id-1', _key: 'abc' },
		{ _type: 'reference', _ref: 'item-id-2', _key: 'def' }
	];
}
```

## Validation

**Available rules:** `required()`, `custom(fn)`, `error(msg)`, `warning(msg)`, `info(msg)`
